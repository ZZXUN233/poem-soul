## 问题现象

从**列表页**（搜索结果页 `/search`、首页「浏览全部」书架 `/`）向下滚动后点进一首诗，
再点阅读页顶部「← 返回」回到列表时，**滚动位置被重置到页首（scrollY=0）**，需用户手动滑回之前的位置。

实测对照：

| 场景 | 返回后 scrollY | 是否恢复 |
| --- | --- | --- |
| 搜索结果页滚到 900 → 点诗 → 返回 | 0 | ❌ 未恢复 |
| 首页书架翻到第 2 页 + 筛朝代 → 点诗 → 返回 | URL 正确恢复（`?dynasty=唐&page=2`），但列表滚动归零 | ⚠️ 分页保留了、滚动位置丢了 |
| 诗歌 → 相关推荐 → 另一首诗 → 返回 | 672（原位置） | ✅ 正常恢复 |

即：**诗→诗的纯服务端页面返回能恢复滚动；列表页返回时滚动丢失**。

## 验证回路

通过 Playwright 驱动 `npm run dev`（localhost:3000）复现：

```text
# 复现：搜索列表 → 诗 → 返回
访问 /search?q=月&mode=classic
window.scrollTo(0, 900)   // 向下滚动
点第一首命中（/poem/...）→ 点「返回」
- 期望：回到 /search?...，scrollY ≈ 900
- 红：scrollY = 0（回到顶部）
```

## 根因分析

Next.js App Router 的 `router.back()` 对历史遍历本应恢复滚动位置，但该恢复对
`force-dynamic` + 返回时**重新挂载/重新 fetch 数据的列表页不生效**：

- 搜索页与书架都是客户端组件，返回时组件重新 mount、重新拉取 `/api/search` / `/api/browse`，
  DOM 重新渲染，浏览器/框架的滚动缓存被清掉，最终落到顶部。
- 诗歌详情页是服务端渲染 + 本次会话内 RSC 载荷有缓存，返回时能恢复位置，故诗句→诗正常。

> 注：本次实现的「书架状态 URL 化」已保证**分页与筛选**在返回时精确保留（URL 驱动），
> 只是**垂直滚动位置**这个维度仍缺失，二者是不同层次的问题。

## 候选方案（未实施，待确认）

1. **浏览器原生 ScrollRestoration**：`window.history.scrollRestoration = "manual"`，
   自行在列表滚动时记录 `scrollY`，返回时恢复。全局但需自管各列表位置。
2. **手动记住 scrollY**（推荐方向）：在 `SearchPage` / `Bookshelf` 用模块级或 session 级变量
   记录离开列表时的 `scrollY`（路由离开前存储，返回后 `useEffect` 中 `window.scrollTo` 恢复）。
   改动局部、不动全局浏览器行为。
3. **锚点/标签定位**：依赖列表项稳定 id，返回时滚到对应项——与分页联动较复杂，优先级低。

## 修复边界

- 本问题与「书架 URL 化（保留分页）」「返回上一级」为同级体验优化，三者独立。
- 记录时已核实：诗→诗返回滚动恢复正常；列表→诗→返回存在此缺陷。
