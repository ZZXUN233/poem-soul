## 问题现象

共 3 个相关联问题，均与页面顶部的「古诗词 / 现代诗」模式切换有关：

1. **默认模式错位**：URL 无 `?mode=` 时，头部模式开关会被 localStorage 里的旧选择（如上次选过「现代诗」）覆盖，标题显示「现代诗」高亮，但正文与服务端渲染仍是古诗词（76,253 首）——肉眼可见的模式错位，违背「URL 无模式时应默认展示古诗词」。

2. **搜索页与模式不匹配 + 切换不清空条件**：
   - 停在「现代诗」（`/?mode=modern`）时点顶部「搜索」，跳转到的 `/search` 没有携带 mode，结果打开却是古诗词搜索页（提示"检索**古诗词**语料库"、出现朝代/体裁过滤栏），与当前模式不符。
   - 在搜索页输入关键词并搜索后（如 `q=月`）再切换模式，URL 变成 `/search?mode=modern&q=月`，搜索条件 `q=月` 被保留下来、仍在跨模式检索旧关键词，未按要求清理搜索条件。

3. **古诗词搜索页「全部」无法点击**：筛选栏默认「全部」高亮，点击某个具体分类（如朝代「唐」）后，「全部」按钮点击无任何效果，朝代过滤无法清除回「全部」。

## 验证回路

通过 Playwright 驱动 `npm run dev`（localhost:3000）复现三个红场景：

```text

浏览器执行 localStorage.setItem('peomsoul-mode','modern') 后访问 /

- 红：现代诗 pill 高亮，而 hero-stats 仍为 76,253（古诗词）

访问 /?mode=modern → 点击顶部「搜索」

- 红：跳转 /search（无 mode），notice 显示"检索古诗词"，出现 filter-bar
```

## 根因分析

| # | 假设 | 是否命中 |
| --- | --- | --- |
| 1 | ModeToggle 用 localStorage 覆盖 URL 语义导致标题与内容错位 | ✅（问题 1） |
| 2 | 导航「搜索」是裸 `<Link href="/search">`，未携带当前 mode | ✅（问题 2 前段） |
| 3 | ModeToggle 切换模式时对 `/search` 保留全部 query 参数，未清理搜索条件 | ✅（问题 2 后段） |
| 4 | SearchPage.syncUrl 用 `updates.dynasty ?? dynasty`，undefined 无法清除条件 | ✅（问题 3） |

**最终根因**：

- **问题 1**：`ModeToggle` 的 `useEffect` 在无 `?mode=` 时读取 `localStorage["peomsoul-mode"]` 并覆盖 `current`，而服务端各页（`page.tsx` / `search/page.tsx`）始终以 `sp.mode ?? "classic"` 渲染、不读 localStorage。两处状态源不一致 → 标题与正文模式错位。
- **问题 2**：导航「搜索」为静态 `<Link href="/search">`，不感知当前模式；`ModeToggle.switchTo` 对 `/search` 走通用分支保留全部 query，导致切换后搜索条件残留。
- **问题 3**：`SearchPage.syncUrl` 用 `updates.dynasty ?? dynasty`，把「显式传 undefined 表示清空」与「参数缺失表示保留」混为一谈，`undefined ?? 当前值` 回退到当前值，故点「全部」永远清不掉过滤条件。

## 修复方案

1. **ModeToggle**（问题 1 + 2 后段）：
   - 删除读取 localStorage 覆盖 `current` 的 `useEffect`，模式完全由 `?mode=` 决定、缺省 `DEFAULT_MODE`（classic），与服务端渲染保持一致；同时移除无用的 `storeMode` 调用。
   - 在 `switchTo` 中针对 `pathname === "/search"` 特判：切换模式时清空搜索条件（q/朝代/体裁/命中/页码），仅保留 `mode` 参数后跳转。

2. **新增 SearchNavLink 客户端组件**（问题 2 前段）：读取当前 `?mode=`，用 `modeHref("/search", mode)` 生成带模式的搜索链接；在 `layout.tsx` 中替换裸 `<Link href="/search">`，并用 `<Suspense>` 包裹（`useSearchParams` 需 Suspense）。

3. **SearchPage.syncUrl**（问题 3）：用 `Object.hasOwnProperty.call(updates, key)` 区分「未传」（保留当前值）与「显式传 undefined」（清空该参数），替换原有的 `??` 回退逻辑。

## 预防建议

- **单一状态源**：模式应始终以 URL `?mode=` 为唯一真值，缺省固定 classic，避免「URL 与服务端渲染 + 客户端 localStorage」三处状态不一致。若要「记住上次模式」，应统一改由 URL / cookie 在服务端解析，而非客户端 localStorage 覆盖。
- **可选参数清空语义**：URL 组装（`syncUrl` / `modeHref` 类工具）应对「参数缺失=保留」与「显式传 undefined=清空」做出统一约定，并抽取成可单测工具函数，避免多处手写 `??` 回退。
- **无正确测试接缝**：这三个问题均落在客户端交互组件（ModeToggle / SearchPage / FilterBar），当前仅 `scripts/search.core.test.mts` 覆盖纯函数层，组件行为无自动化测试。建议后续为模式切换、筛选栏补充组件测试（或至少为 `syncUrl` / URL 组装抽纯函数加测试），把这些交互逻辑锁死。
